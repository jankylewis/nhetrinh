04 · DESIGN RULES

Light first,
fast second.

nhetrinh exists to be light. Four limits set its size. A few rules keep every change inside them.

1 · The four limits

WhatLimitHow nhetrinh stays under it
Memory of the app itself40 MBPages live in WebKit's helper programs, not in the app
Memory of the app and its helpers110 MBOnly shown tabs load; unused tabs rest
Size of the app on disk1 MBThe engine comes with the Mac; no outside code
CPU while you do nothing2 %Nothing runs in a loop; work starts only when something happens

Today the app is 1,048 KB. That is a little over 1 MB.

More features wait on other branches, and they add size.

The headmate decides: raise the limit, or cut something.

A change that breaks a limit stops until the cost is gone or the headmate accepts a new limit.

3 · Rules that keep it right

TEST FIRSTWrite the test first, then the code. A bug fix starts with a test that fails. A test that cannot fail is a bug too.
USE ITDone means used. The checker uses the installed app as you do. "Merged" and "tests pass" do not mean done.
WRITE IT DOWNEvery bug, failure, lesson and feature gets a note in hubs/, in the same change. The note says who found it and what proves it.
YOUR MACBuilds and tests run at low priority, one big job at a time. The app you use is never restarted or replaced without your OK.
PUBLICAnyone can read the code. So no secrets, names, work details or personal paths go in it. Sign-ins stay in the Keychain. Cookie values never go in a log.
